# 2026-11-27: control port, part 1 of 3 (issue 195)

Added an opt-in loopback control port to the desktop app (`apps/laserfoundry/src/control.rs`).

- Off by default. `--control <port>` / `--control=<port>` or `LASERFOUNDRY_CONTROL_PORT`; a value outside 1-65535 stops the app with a message (exit 2).
- Binds `127.0.0.1` only, one client at a time, lines capped at 1 MiB (the connection is closed), 100 requests per second per client.
- Methods: `engine.execute {command, params}`, `engine.commands`, `ui.inspect` (tool, panels, selection, shape count, window size, fps).
- Requests run on the app thread once per frame (16 at most). Machine actions (jobs, jog, fire, serial) are not methods, so they are unreachable.
- Checked with unit tests (port parsing, protocol, hostile input, a real loopback socket round trip, the line cap).

`docs/control-protocol.md`, CLAUDE.md line. Unknown parameter keys are not yet reported with the nearest key (the engine takes untyped params).
