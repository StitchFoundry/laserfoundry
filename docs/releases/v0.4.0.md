## LaserFoundry 0.4.0

This release is mostly about **connecting and setting up**: pick your laser from published spec sheets in the setup wizard, run a laser-off first-mark test grid with a safety checklist, and reconnect in the browser without choosing the port again. It also fixes a safety bug: **resuming a job after an M5 no longer switches the laser back on.**

> **This is still an early release.** Everything that talks to a machine has been tested only against the built-in simulator, not on real hardware. Read
> [`docs/hardware-bringup.md`](https://github.com/StitchFoundry/laserfoundry/blob/main/docs/hardware-bringup.md) before your first job: it covers safety, a laser-off motion test and
> first marks on scrap material. LaserFoundry is independent of, and unaffiliated with, other laser software vendors.

### What's new

- **Pick your laser from published spec sheets.** The setup wizard can fill in bed size and limits from a list of machines, each entry linked to its source. Check an entry against its link before trusting it.
- **First-mark test grid.** The wizard can draw a small test grid with a safety checklist, so you can check position and power on scrap before a real job.
- **Resuming after M5 is safe.** Resuming a job that was stopped with M5 no longer switches the laser back on (#76).
- **A restarted job that stops again keeps its place** in the design's program, so the "A job was interrupted" offer works again (#90).
- **Web app serial connection.** The port is closed and its locks released on disconnect or a failed connect; a port you already granted reopens without the picker; DTR and RTS are set low after open and before close (for boards that reset when the port opens); and an **alarm banner with an Unlock button** sits in the Machine block.
- **Web app text.** SVG text is drawn with the loaded library fonts, and text it cannot draw is reported instead of silently dropped (#68).
- **Sign-in.** "Use my own Anthropic API key" is gone: the Foundry Account is the only sign-in.
- **Camera groundwork (not a user feature yet).** Lens model, bed homography, camera profiles and checkerboard detection, a first parametric camera bracket, and a recommended-cameras page.
- **Behind the scenes.** A staging switch for the web app, a dependency security bump (rustix), lockfile fixes, and CI mirror retries.

### Known issues

- Not tested on real hardware. The web serial changes in particular need a real board.
- Camera support is groundwork only: there is no camera button in the app yet.
