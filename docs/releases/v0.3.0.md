## LaserFoundry 0.3.0

The headline is the **machine setup wizard**: connect, let LaserFoundry read your machine's settings, check with the laser off that
the head moves the way you expect and reaches the whole bed, then name and save the machine. This release also folds in everything
from the unpublished 0.2.1: you can name the design you send to MakerFoundry, there are two new links in the Help menu, **a GRBL
job now waits for the machine to answer earlier commands before it starts sending**, two crash and hang fixes for hostile files,
and several job-size and safety limits are tightened.

> **This is still an early release.** Everything that talks to a machine has been tested only against the built-in simulator, not
> on real hardware. Read
> [`docs/hardware-bringup.md`](https://github.com/StitchFoundry/laserfoundry/blob/main/docs/hardware-bringup.md) before your first job: it covers safety, a laser-off motion test and
> first marks on scrap material. LaserFoundry is independent of, and unaffiliated with, other laser software vendors.

### What's new

- **Machine block.** The right panel now starts with a **Machine** block: its status (Disconnected, Ready, Busy or Alarm, or
  `Simulator: …`), name, bed size, origin, the connection controls and a **Machine settings…** button.
- **Machine setup wizard.** **Laser → Machine setup…** walks you through it, and you can skip it at any point. It connects (to the
  simulator or a serial port), reads the machine's settings (bed size, maximum laser power, homing and laser mode, with a button to
  turn laser mode on if it is off), runs a **direction test with the laser off** (it tells you if an axis is reversed and offers to
  flip it), then lets you name and save the machine. On the desktop app it opens by itself the first time, and not again once you
  skip or save it.
- **Bed check.** A new wizard step traces the outline of the bed with the laser off (power S0) and asks whether the head reached
  every corner without touching the frame. Answer "No" and the bed is made 10 mm smaller each way (never below 10 mm) so you can
  try again. The same outline is available as the command `machine.bed_outline`.
- **Name your design for MakerFoundry.** **File › Publish to MakerFoundry…** now has a Name field. The draft on MakerFoundry takes its
  title from it (letters, digits, spaces, `-` and `_`; anything else becomes `_`; at most 60 characters). Leave it empty and the
  publish is refused with a message, so a draft is never created with a placeholder title.
- **Opening designs from MakerFoundry works with real designs.** Checked in the browser version against two published test
  designs, one SVG and one DXF: the file name comes from MakerFoundry's answer, and the drawing opens at its true size.
- **Help links.** **Help › MakerFoundry on YouTube…** opens the MakerFoundry channel, and **Help › Support the Project…** opens a
  Buy Me a Coffee page if you want to chip in. It is optional and unlocks nothing. Nothing is sent when you click either.
- **Links point at the StitchFoundry organisation.** The links in the app, the README and the web pages now use the new
  StitchFoundry address on GitHub, and the font download comes from the StitchFoundry fonts repository.
- **AI: an unconfirmed email is explained, not treated as signed out.** If your StitchFoundry account's email is not confirmed yet,
  the AI window now shows the service's own message (it says where the confirmation link was sent) and keeps you signed in. Before,
  it asked you to sign in again and forgot your session. Tested against a scripted service, not the live one.

### Changed: how a GRBL job starts (machine control)

- **A GRBL job waits until the machine has answered earlier commands.** If you press Start while the machine is still busy with
  something you sent just before (for example Home, which can take a while), LaserFoundry used to start streaming the job straight
  away. The machine's late "ok" for Home was then mistaken for the job's first line, so the app could send more than the machine's
  small input buffer holds, with the laser on. Now the job sends nothing until every earlier command is answered: the console says
  it is waiting, an alarm while it waits ends the job before any line is sent, and a machine that never answers ends it after the
  usual idle timeout. Stop still clears everything. The Marlin link already worked this way and is unchanged.
  **Tested against the built-in simulator and a scripted controller only, not on real hardware.** If you run GRBL, try a laser-off
  job right after Home first and tell us if a job sits "waiting" when it shouldn't.

### Fixed

- **Framing refuses feed rates above the maximum.** Asking to frame a job with a speed above 1,000,000 mm/min (from a script or the
  command line) used to produce a `G1` line with an absurdly long feed number. It is now refused, as full jobs already were.
- **G-code refuses rotary diameters that would overflow Y.** A project file could carry rotary diameters the settings dialog would
  never accept (for example 1e300 and 1e-300), and the program then contained a `Yinf` move. Diameters outside 1 to 10,000 mm are now
  refused when the G-code is made, and every scaled coordinate is checked.
- **A project with a picture that has no pixels no longer crashes.** A hand-made or damaged project file with a zero-width or
  zero-height picture made planning (preview, `laserfoundry-cli info` and `gcode`) crash. It is now refused on open with "image has
  no pixels", and the cut planner treats an empty picture as white (nothing burned) wherever it comes from.
- **DXF files with many copies of a curved block can no longer hang the import.** Each placed copy of a block re-calculated its curves,
  so a small hostile file could keep the import busy for hours. Curves are now calculated once per block (the result is exactly the
  same), and an import that would still need too much work stops with "the drawing is too complex to import" instead of hanging or
  running out of memory. Not yet tried on large real-world DXF files near the new limits.
- **The job-size limit now counts every pass.** A layer set to many passes could slip past the limit on the number of moves in a
  job and make the program run out of memory while it planned the cut; the limit now counts moves times passes.

### Dependencies

- `async-executor` 1.14.1 (1.14.0 was withdrawn by its authors); it is only used by the Linux screen-reader support.
- Updated the SVG reader (`usvg` 0.49), the text shaper (`harfrust` 0.15), the font reader (`skrifa` 0.49) and the XML reader
  (`roxmltree` 0.21.2), plus two CI actions (Windows signing, build cache). SVG import and text are covered by the test suite
  but have had less real-world use with these versions: please report anything that imports differently from 0.2.0.

### Upgrading from 0.2.0

Project files open unchanged, except a damaged one holding a picture with no pixels, which is now refused instead of crashing, and
one with rotary diameters outside 1 to 10,000 mm, which no longer produces G-code. The machine is still saved inside the project, so
a new project starts from the default machine.

### Also in this release

More tests (sampled pictures, framing refusals, SVG import, G-code resume) and nightly maintenance; wording changes in the README and
docs. No change to what the app does.

### Known issues

- **The web app drops SVG text on import** (#68). Text in an SVG opened in the browser version does not appear. Convert the text to
  paths in your drawing program first.

### Known limits

- **Not run on real hardware.** Every machine feature is verified against the simulator and the controllers' public documentation
  only, and the setup wizard has not been run against a real controller. Please report what you find; the app can save a machine
  report (**Laser → Save machine report**) with nothing private in it.
- **Setup wizard:** a first-mark test grid, finding your laser automatically, laser presets and several saved machines are not done yet.
- **Other controllers:** the Marlin-laser and Smoothieware support is untested on hardware. There is no Ruida support.
- **Signing:** the signed Windows and macOS builds have not yet been checked on a fresh machine, so the SmartScreen and
  Gatekeeper first-run experience is unconfirmed.
- **Scope:** this covers a fraction of what established laser software does.
  [`docs/feature-checklist.md`](https://github.com/StitchFoundry/laserfoundry/blob/main/docs/feature-checklist.md)
  is an honest self-assessment and [`docs/gaps.md`](https://github.com/StitchFoundry/laserfoundry/blob/main/docs/gaps.md) is the ranked work list.
